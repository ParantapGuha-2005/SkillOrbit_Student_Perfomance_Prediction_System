# 🎓 Student Performance Prediction System

A machine learning capstone project that analyses student academic data, predicts performance levels (Low / Average / High), and surfaces the insights through an interactive Streamlit dashboard with rule-based improvement recommendations.

Built as part of the SkillOrbit Machine Learning internship.

**Author:** Parantap Guha

---

## 📋 Overview

Given raw student records (attendance, study hours, previous grades, extracurricular activity, parental support, etc.), this project:

- Cleans and preprocesses messy, real-world-style data (inconsistent casing, decoy/noisy columns, duplicates, missing values, outliers)
- Explores which factors are most associated with student performance
- Trains and compares four models — Logistic Regression, Linear Regression, Decision Tree, and Random Forest — against a majority-class baseline
- Packages the best model into an interactive dashboard for exploring individual students, contributing factors, and performance trends
- Generates plain-language, rule-based recommendations for improving a student's predicted outcome

## 📓 Notebook Contents

The notebook is organised into the five modules from the project brief:

1. **Data Collection & Preprocessing** — load, inspect, clean, handle missing values, remove duplicates and decoy columns, cap outliers (IQR method), encode categorical features
2. **Exploratory Data Analysis** — performance distribution, attendance/study-hours trends, correlation heatmap, parental support & extracurricular breakdowns
3. **Performance Prediction Model** — baseline, Logistic Regression, Linear Regression (predicting `FinalGrade` and binning it into a performance level for a fair comparison), Decision Tree, and Random Forest, each evaluated with accuracy, precision, recall, and F1
4. **Performance Dashboard** — model comparison table/chart, side-by-side confusion matrices, and an honest discussion of which model actually performed best
5. **Recommendation System** — rule-based tips generated from a student's attendance, study habits, previous grade, extracurricular involvement, and parental support

## 📊 Model Results (Test Set)

| Model                        | Accuracy | Weighted F1 | Macro F1 |
|-------------------------------|:--------:|:-----------:|:--------:|
| Baseline (majority class)     | 59.16%   | 43.98%      | 24.78%   |
| Logistic Regression           | 67.54%   | 66.18%      | 58.64%   |
| Linear Regression (binned)    | 68.59%   | 66.88%      | 60.38%   |
| Decision Tree                 | 53.40%   | 52.66%      | 42.93%   |
| Random Forest                 | 63.35%   | 60.94%      | 51.23%   |

Random Forest is deployed in the dashboard as the most robust non-linear option. However, Linear Regression (repurposed via binning) edged it out on this particular split — mentioned in notebook's Module 4 conclusion.

## 🖥️ Dashboard Features

- **Overview** — dataset summary and model comparison
- **Student Explorer** — look up a student, compare them to class averages, get recommendations
- **Factor Analysis** — how attendance, study hours, previous grade, and other factors relate to performance
- **Performance Trends** — grade trends across attendance and study-hour buckets
- **Predict a New Student** — live, out-of-sample prediction with tailored recommendations

## ⚙️ Setup & Usage

### 1. 📔 Run the notebook
Open `Student_Performance_Prediction_System.ipynb` in Jupyter or Google Colab and run all cells. This trains the models and saves everything the dashboard needs into `artifacts/`.

### 2. 🚀 Run the dashboard
```bash
pip install -r requirements.txt
streamlit run app.py
```
Make sure the `artifacts/` folder (created by the notebook) sits in the same directory as `app.py`.

## 📝 Scope Notes

- This dataset records one overall `FinalGrade` per student rather than per-subject scores, so "subject-wise analysis" is implemented as factor-wise analysis (attendance, study hours, etc.) instead.
- As per the project brief's scope limitations, this system intentionally does not use deep learning, real-time monitoring, or large-scale platform architecture — the focus is a clean, functional prediction pipeline.
